A Random-Post Button, Now With One (1) Link

Is it possible to create a button that links to a random post — in HTML and CSS only? Inspired by “A Button That Links to a Random Post in HTML & CSS Only” by Chris Coyier, where a button-shaped area is secretly dozens of tiny links and where you click picks the post. Delightfully cursed. This page continues the game with one extra house rule: same zero JavaScript, but maybe — just maybe — a screen reader could walk away having met one link instead of all twelve. No promises.

The idea: put all the links together, but keep only one element visible — and pick that element (pseudo-)randomly. Stack the links in a single grid cell, hide them all, and let an infinite animation decide which one exists right now: 

<nav class="random-post" aria-label="Random post">
  <a href="/post-1/">Random post</a>
  <a href="/post-2/">Random post</a>
  <!-- …one per post -->
</nav>

/* stack all the links in one spot, hide them all */
.random-post   { display: inline-grid; }
.random-post a { grid-area: 1 / 1; visibility: hidden; }

/* the pseudo-random part: each link exists for 1/12 of the cycle */
@keyframes cycle {
  from        { visibility: visible; }
  8.3333%, to { visibility: hidden; }
}
.random-post a              { animation: cycle 3s infinite; }
.random-post a:nth-child(2) { animation-delay: -0.25s; }
.random-post a:nth-child(3) { animation-delay: -0.5s; }
/* …one slot per link */

/* reaching for the button freezes the roll */
.random-post:is(:hover, :focus-within) a { animation-play-state: paused; }

Links with visibility: hidden take up no space, receive no clicks, and are skipped by the Tab key and screen readers. At any moment, exactly one link is rendered. The other eleven are a rumor.

The seed — where does the randomness come from?

CSS is getting a real random() function. It currently ships in roughly one browser, which in CSS years means “soon”. Until then, the seed is whatever never stops changing — sampled at the moment the user interacts. Three seeds, three demos below:

  1. The clock — an infinite animation cycles through the links; hovering or focusing the button freezes the pick (Option 1).
  2. The scrollbar — how far you've scrolled picks the link (Option 2).
  3. Your mouse path — the last hover zone your pointer crossed picks it, and a CSS latch remembers (Option 3).

Option 1 — the clock is the dice

The cycle runs four times a second — the die tumbles while it runs, and both freeze the moment you reach for the button. Your reaction time is the RNG.

Option 2 — the scrollbar is the dice

Each link only exists inside its slice of the page's scroll range (animation-timeline: scroll(root) + animation-range): the scroll position at click time is the pick. The accessibility tree only changes while the user scrolls. The die is scroll-driven too — yes, this is farming entropy from your mouse wheel.

Option 3 — your mouse path is the dice

Twelve inert aria-hidden hover zones form a moat around one real link. The last zone the pointer crossed is remembered by a CSS latch — a transition with an ~11-day delay, which is what we call state management now. Keyboard and screen reader users see one link.
